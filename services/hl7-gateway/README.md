# HL7 gateway (Mirth Connect)

Mirth Connect **4.5.2** (the last MPL-licensed release) receives HL7v2 over MLLP and hands
clinical facts to the ScoutOSS indexer.

```
EHR / interface engine ──MLLP :6661──▶ Mirth channel "ScoutOSS HL7 ingest"
   source transformer (channel/transformer.js): HL7 → {"events": [...]} JSON
   HTTP Sender ──POST /clinical/events (Bearer, traceparent)──▶ indexer
        pseudonymize PID-3 (HMAC, same salt as DICOM) → shift dates → scrub free text
        → Postgres clinical.* + OpenSearch clinical_events → dicom_patients.diagnoses
   ACK: AA when the indexer accepted the batch, AE otherwise (sender retries)
```

| Message   | Extracted                                                     |
|-----------|---------------------------------------------------------------|
| ADT^A01/A08 | demographics (PID-3/7/8), diagnoses (DG1-3 ICD-10)          |
| ORM^O01   | orders (OBR-4) + diagnoses                                    |
| ORU^R01   | results (OBX-3/5/6/8)                                         |

## PHI handling

* The channel stores **metadata only** and removes content on completion
  (`messageStorageMode=METADATA`, `removeContentOnCompletion=true`, content encryption on),
  so no raw HL7 is retained in Mirth's database.
* Mirth authenticates to the indexer with the `scoutoss-mirth` Keycloak client
  (client-credentials, role `service`); the indexer is the only component that sees the MRN,
  and only long enough to compute the pseudonym.

## Files

* `channel/transformer.js` — the source transformer (edit this).
* `channel/scoutoss-hl7-ingest.xml` — Mirth channel export, generated by
  `python scripts/gen_mirth_channel.py`. Import it in the Mirth Administrator or let
  `mirth-setup` (scripts/bootstrap/mirth.py) deploy it via the REST API on `make up`.

## Sending test messages

`make seed` sends ADT/ORM/ORU messages for the synthetic patients (three with lung cancer,
ICD-10 C34.90). Manually:

```bash
printf '\x0bMSH|^~\\&|EHR|SITE|SCOUTOSS|SCOUT|20240101||ADT^A01|MSG1|P|2.5.1\rPID|1||MRN1^^^SITE^MR||Doe^Jane||19600101|F\rDG1|1|I10|C34.90^Lung cancer^I10\x1c\x0d' | nc 127.0.0.1 26661
```

## FHIR (optional)

For FHIR R4 feeds, run HAPI FHIR (`hapiproject/hapi:v8.2.0`) and add a Mirth channel with an
HTTP Listener → the same indexer endpoint; the JSON event shape is identical.
